后续功能仍按依赖关系推进，以下条目不计入本轮完成范围：

- [ ] 旧式 Forge、特殊 NeoForge 坐标和加载器官方在线/Windows 端到端验证；已完成的现代安装流程不代表所有历史版本可用。
- [ ] 在现有 GUI 安装确认及 MCP 受限计划基础上，补全通用计划 GUI 审批、跨文件崩溃自动恢复与通用事务。
- [ ] 完整运行期兼容性模拟、整合包内自动准备加载器、锁定文件与整合包导入导出（当前支持静态求解及 mrpack 内容安装）。
- [ ] 自动组包、非侵入式汉化和启动验证。
- [ ] 开机自启、系统托盘、多语言、完整数据备份恢复/重置、自动更新程序；非 Windows 系统凭据存储。常规配置导入导出只覆盖常规选项，缓存移动不释放磁盘空间。

资源详情中的依赖列表是源站元数据；Mod 安装预览会回溯选择必需依赖，再读取实际 JAR 检查本地组合，未知元数据明确提示。对话回复不执行本地工具或安装操作。

规则与依赖求解续做验证：工作区编译检查通过，项目自有测试 180 项通过、21 项跳过；另行通过四张截图和真实 Modrinth 只读依赖求解。范围与保留项见[说明](dependency-resolution-and-rules.md)。

此前加载器与日志续做验证：工作区编译检查通过，项目自有测试 162 项通过、19 项跳过，四张新流程截图通过；官方在线安装和 Windows 原生验证未执行，详见对应[说明](loaders-and-diagnostics.md)。

此前资源与工作区验证：`cargo check --workspace` 通过，项目自有测试共 129 项通过；另行通过四类 Modrinth 在线目录/版本查询测试。实例管理补充验证见其[功能说明](instance-management.md)。本次续做的验证和平台边界见[常规设置说明](general-settings.md)。桌面截图检查使用 Linux tiny-skia 后端，不等同于原生 Windows 登录或游戏启动验证。

验证入口：

```sh
cargo check --workspace --locked --offline
ICED_TEST_BACKEND=tiny-skia cargo test --locked --offline -p desktop -p mc-core -p mc-mcp -- --test-threads=1
cargo test --locked --offline -p mc-core live_resource_categories_and_versions_are_reachable -- --ignored
```

新增回环 HTTP 测试验证实际请求参数、多轮上下文、失败处理、四类资源筛选与分页；控件测试覆盖 1024×680 和 1536×921。在线测试另行访问 Modrinth 的四类目录和版本接口；它不验证第三方安装或 Microsoft 登录。

MCP 来源安装用回环 HTTP 验证了真实请求路径、固定文件、哈希与 Key 隔离；尚未完成真实 CurseForge Key 的在线安装或实际 FTB 客户端视觉/进度验证。FTB 目前适配 1.20.1 SNBT，物品检查依赖用户导入真实注册表。
